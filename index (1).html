The life of a request

Every call follows the same four stops. Nothing skips the gatekeeper.

  1. 💻

    Client sends

    The browser or an app sends a JSON request with a method and a path.

  2. 🛡️

    Gatekeeper checks

    Content type, JSON format and every field are validated first.

  3. 🧠

    Brain decides

    The handler finds the record, applies the rules and builds the answer.

  4. 🗄️

    Store remembers

    Changes are saved, then the client gets a status code and JSON back.

      The gatekeeper rule

      Never trust the client. Every request passes four layers before it can change data. Drag the slider to pull them apart.

      • Content type must be JSON (415 if not).
      • Syntactic: name 2 to 60 characters, a valid email, age 13 to 120, role student, developer or admin (400 if not).
      • Semantic: the email must be unique (409 if taken).
      • Handler: unknown ids return 404, wrong methods return 405.

      Run it on your computer

      The server needs only Node.js 18 or newer. There is nothing to install.

      node server.js
# open http://localhost:3000 for this console
# the API and this page run from the same server
      curl http://localhost:3000/users
curl -X POST http://localhost:3000/users -H "Content-Type: application/json" -d '{"name":"Ayesha Khan","email":"ayesha@example.com"}'

      Data is kept in memory and saved to data.json, so it survives a restart. The server also answers 429 after 100 requests a minute from one address.
